# 路线图

> 原则：先基建，再能力，再界面；每个里程碑有明确的出口标准，通过后才进入下一个。出口标准里的指标见 [metrics.md](metrics.md)。**每个引入新模块的里程碑，出口标准都隐含一条：该模块已完成首轮消融并记录结论**（[evaluation §9](evaluation.md)）。

| 里程碑 | 内容 | 出口标准 |
|---|---|---|
| **M0 收敛** | PRD、指标体系、架构、决策记录、评测方案、路线图；仓库与工程规则 | 文档评审通过；仓库骨架、CI 就绪 |
| **M1 基建** | 配置与密钥；领域模型；事件 / trace 与 SQLite 存储；LLM 网关（角色、流式、缓存友好提示布局、录制回放、成本与缓存统计）；知识层适配；沙箱；阶段 / 工具 / 管线框架；FastAPI 骨架（会话、轮次、SSE、调试接口）；评测框架（用例加载、运行器、指标计算、报告）；探针 S1（导出）、S3（部署形态）；`Dockerfile` 草案 | L1 不变量全绿；一个"空管线"从 API 走到 SSE 且 trace 完整（F6 = 0）；评测框架能在 replay 模式下对样例用例出报告；模型延迟与缓存命中基线记录在案 |
| **M2 理解** | `route` + `understand`（Brief、澄清、假设）；评测集（场景用例）与基线；模型角色对比（fast） | B1 ≥ 0.90、B2、B3 达标；澄清轮次占比 ≤ 15% |
| **M3 规划与生成** | `knowledge` 图检索与 `ComboMiner`；`plan`；`produce`（write、核验、修复）；`template` 来源；模型角色对比（smart / solver / judge） | A2、A3 过闸门；A5、A6 达标；A1 有基线与初步提升 |
| **D1 调试台** | 运行列表、流程 / 时间线、图检索视图、步骤检查器、题目证据、badcase 入库、AI 分析（围绕一次运行对话，D56） | 能复现并定位 M2–M3 的任一失败样本；图检索视图可回放 |
| **M4 感知** | 图像预处理、`perceive`、学生上下文、防雷同；拍照评测集与基线；vision 模型对比 | B4、B5 达标；S3 场景端到端可用 |
| **M5 试卷** | `assemble`、Patch 与修订、`edit`（自然语言）、组卷分阶段与检查点、`answer` | C1 ≥ 0.90；S4 蓝图 → 样题 → 全卷可用 |
| **M6 导出** | `figures`（首批图形类型）、`render`（PDF、Word、Markdown、LaTeX） | C4 闸门达标；公式与版面人工抽检通过 |
| **U1 用户端** | 对话、拍照上传、工作台 / 试卷视图、编辑器、导出、进度与假设芯片 | 脚本化用户走通 S1–S8（含 S3 拍照）；FR-1～FR-10 的 AC 全部满足 |
| **M8 对外版本** | 端到端评测（test 划分）、性能与成本调优、Docker 与 Zeabur 部署、文档与 README | 见 [evaluation.md §7](evaluation.md)；他人按文档可复现部署 |

调试台（D1）刻意放在 M3 之后、用户端之前：它是后续所有迭代的"显微镜"，越早越能降低迭代成本。

## 尚未达到的目标

按产品标准定的门槛不放宽，如实列出（数字来自留出集验收，[produce.md §8.1](../eval/specs/produce.md)）：

- **需求贴合与题量**：题量达成率 0.670（目标 ≥ 0.95）；按要求题数算的可用率 0.524，低于一次直出的 0.669。交付出来的题更可靠（答案正确 0.966 对 0.838），但老师点名的主题只能看图出题或超出所说年级、以及"只要计算题""课本那种基础题"这类形式要求，处理得不好。
- **A2(a) 0.973**（目标 ≥ 0.99）、**A3 0.094**（目标 ≤ 0.02）：A3 的审计口径里有知识库词表缺项与过严的概念判定（`eval/badcases/`），先校准再判定。
- **时延**：首题 p50 21 秒（目标 25 秒，达标）；全部上屏 p50 73 秒（目标 60 秒）。

## 后续方向

1. **需求贴合**：先在评测集里补上留出集暴露的请求形态（看图主题、年级错配、指定题型 / 情境 / "课本那种"），再修——主题无法出题时先告诉老师并给出选项；形式要求由代码约束、不让"考法多样"盖过原话。
2. 理解阶段：教师说的年级与主题在教材里对不上时（"三年级的面积"），先说明并给出选项。
3. 知识库：几何词表、概念边界的修正反馈给 ChalkBase（`eval/badcases/` 里标 `K` 的条目）。
4. 图形：组合图形与立体图形。
5. 拍照：页面底部应用题的漏读与共享一张图的小问（[perceive.md §5.6](../eval/specs/perceive.md)）。
6. 调试台：从某一阶段重放、两次运行对比。
