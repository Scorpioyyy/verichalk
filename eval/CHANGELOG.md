# 评测变更记录

评测定义与评测数据的每一次调整都记在这里：改了什么、为什么、对历史结果的影响。原则：**不允许为了过线修改评测**；修正标注错误、补充区分度不足的用例是允许的，但必须在使用 test 划分验收之前完成，并用新定义重算历史版本。

## 2026-10-05　意图理解（M2）

1. **指标 B1 的定义细化**：metrics.md 原定义为"字段级 F1"。实现时发现期望是"部分标注"（只写有把握的字段），精确率没有可靠的分母，改为：**字段通过率**（写出的字段检查通过的比例）+ **幻觉率**（`absent` 字段被断言的比例）+ **来源准确率**（`user_fields` 中带 `origin=user` 的比例）三项，覆盖原 F1 想衡量的两面（漏解析 / 凭空断言）。基线与模型版都用新定义，没有历史结果受影响。
2. **标注错误修正（基线已跑过一次之后、test 划分使用之前）**：错误分析发现用例生成时期望键 `scenes_any` / `constraints_any` 与"不应断言"列表里的 `scenes` / `constraints` 对不上，导致 13 个有情境 / 限制的用例被错误地要求"不得断言情境 / 限制"；`u-e07` 的题型期望把"两步计算题"标成了应用题（应为计算题）并多写了 `absent: topics`；`u-l17`（提示注入夹带初中内容）期望改为 `offtopic`（用户最终意图是初中内容，且这是注入用例，拒绝是安全且合理的）。修正后用新标注重算了规则基线与模型版。
3. **评测集区分度不足**：规则基线与模型版在作者撰写的 val 集上 B1 几乎持平（0.945 vs 0.963，置信区间大幅重叠）。原因是用例由规则的作者撰写，说法偏规整（作者偏差）。处理：增加由**不同厂商模型改写**的"换说法"用例集（`understand_para`），保持意图不变、说法更口语 / 省略 / 语序多样，并经两个模型核验"意图未变"后才入集。few-shot 示例与评测集的说法保持不重合。

4. **test 划分的使用记录（M2 验收）**：第一次验收（提示词 v2）后查看了失败样本并做了通用修复，因此 `understand` / `understand_para` 的 test 划分**不再是干净的留出集**；文档里相应的数字标注为"事后修复"。为此新增 `understand_fresh`（42 例，全部是新写的说法与主题，重点是小学 / 初中内容的边界、跨年级主题、范围冲突、不同口吻），它在修复之后才第一次被系统看到。**规则：每次据 test 失败样本改动系统后，验收前必须补一批新的未见用例。**
5. **标注规范补充**（`eval/annotation/understand/guideline.md` §7）：①"同类 / 类似 / 照着类型再出"表达的是档位（consolidate），不是 `source: template`；②"口算 / 计算 / 竖式"是题型不是主题；③"串起来 / 放一块儿 / 结合"都表示 integrated。均来自模型与标注分歧的错误分析，不改变已有用例的期望（已有用例的期望本就符合这些解释）。
6. **换说法集的清理**：改写模型对原话 `。。。` 等无意义输入"脑补"出带 `××` 占位符的模板，已剔除这类改写，并在构建脚本里加入过滤（无汉字 / 过短的原话不改写；含 `××` 的改写丢弃）。
7. **录制的更新**：消融实验使用实录模式（按温度 0.3 重新调用模型并覆盖录制），因此每次消融后回放数字会有细微变化（约 ±1～3 个字段检查）。文档里的最终数字取自最后一次回放。
