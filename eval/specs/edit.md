# M5 试卷（assemble / edit / answer / 组卷）评测规格

范围：让"出一批题"变成"一份可以持续修改的试卷"。包括：①**修订机制**（手动编辑、撤销 / 重做、历史与回退、手改后复核）；②**装配**（在已有试卷上追加 / 替换，分区、分值、总分、题号）；③**自然语言编辑**（"第 3 题换个场景""整体降一点难度""改成选择题"→ 补丁 → 复核 → diff）；④**组卷分阶段**（蓝图 → 样题 → 全卷，各有检查点）；⑤**追问**（"第 2 题为什么选 B"，只读）。

设计依据：[PRD FR-4 / FR-6 / FR-10](../../docs/prd.md)、[architecture §4.3 / §5](../../docs/architecture.md)、[D22](../../docs/design.md)（修改一律是补丁）。指标见 [metrics.md](../../docs/metrics.md) 的 C1、C2。

## 1. 失败模式与检测手段

| # | 失败模式 | 教师感受 | 检测手段 | 指标 |
|---|---|---|---|---|
| 1 | **改动没有体现**："换个场景"后情境没变；"改成选择题"后还是填空 | 说了没用 | 结构类请求用确定性检查（题型 / 选项数 / 是否被删 / 顺序 / 分值 / 标题）；语义类请求（场景、难度、数字大小）用与改写模型不同源的判官，问"要求是否被体现" | C1① |
| 2 | **附带破坏**：改第 3 题时别的题被动了；改了题干却没改答案 / 解析；换场景时丢了知识点 | 比不改还糟 | 确定性：未点名的题逐字节不变（含 id、rev）；被改的题知识点集合不得丢；被改的题答案 / 解析与新题干一致由复核判定 | C1② |
| 3 | **改完没有复核或复核没过就上屏** | 改出了错题 | 被改写的题必须带新的 `verification`，状态不是 `rejected`；复核证据存在 | C1③ |
| 4 | **目标指错**："第 3 题"指到别的题；分区之间题号错位 | 改错了题 | 目标解析与导出题号同一套编号（`render.view`）；属性测试：编号连续、与导出一致 | C1 / 单元测试 |
| 5 | **撤销 / 重做 / 回退不守恒**：撤销后与改前不同；撤销后再编辑，重做栈没清空；回退后历史丢失 | 不敢改 | 属性测试：任意操作序列后，`undo` 的结果与上一状态逐字段相等；`redo` 与撤销前相等；编辑清空重做栈；历史只增不删 | 单元测试（硬不变量） |
| 6 | **并发覆盖**：手改与后台复核同时落盘，复核把用户刚改的内容覆盖掉 | 改了的字又变回去 | 复核结果只在"该题 rev 未变"时落盘；旧版本的复核结果丢弃 | 单元测试 |
| 7 | **手改后核验状态过期**：改了答案但仍显示"已核验" | 虚假的可信标注 | 内容字段（题干 / 选项 / 答案 / 解析）被改后，状态立即回到 `pending`，并发起复核；手改过的题 `provenance.source = edited`；手改题不可能是"已核验"（没有求解程序，最高"已校对"） | C2 / 单元测试 |
| 8 | **复核太慢**：改完看不到状态 | 等待焦虑 | 手改到状态更新的时延 | C2 |
| 9 | **追加变成覆盖**：说"再来 3 道"却把原有试卷换掉 | 丢了东西 | 追加后原有题逐字节不变、新题在末尾；只有明确说"重出 / 换一批 / 全部换"才替换（且替换可撤销） | 单元测试 + 规则表 |
| 10 | **整卷：分值与总分对不上、题量与时长不匹配、覆盖不全、难度无梯度** | 卷子不能用 | 确定性：各题分值之和 = 总分（精确）；题量按时长估计在合理区间；所选范围内主要知识点被覆盖的比例；难度从易到难单调（分区内） | 蓝图指标 P-A～P-D |
| 11 | **分阶段形同虚设**：蓝图 / 样题检查点不生效，用户改了要求却被忽略 | 白等 | 集成测试：检查点暂停、回应后按回应继续；"确认"与"改一改"两条路径都走通 | 集成测试 |
| 12 | **追问答非所问或与题目矛盾**：解释里的答案与题目答案不同；编造知识点 | 误导学生 | 与回答模型不同源的判官：是否回答了问题、是否与题目的答案 / 解析一致 | S7（判官） |
| 13 | **自然语言指令理解错**（edit vs 重出 vs ask） | 做了别的事 | M2 的路由评测已覆盖；这里只检查 edit 计划的结构合法性与目标范围 | 单元测试 |

## 2. 评测数据

1. **补丁与修订的属性测试**（确定性、零成本，进 pytest）：随机操作序列下的守恒与不变量（失败模式 4、5、6、9）。
2. **编辑评测集** `eval/datasets/edit/cases.yaml`：基础试卷固定（`eval/datasets/edit/papers.yaml`，来自真实产出的 8 题试卷与一份 12 题含多分区的试卷），每个用例 = 一句编辑指令 + 目标 + 期望检查。覆盖：换情境、降 / 升难度、改题型（填空↔选择↔应用↔判断）、数字调整（"数字别太大"）、解析改写（"讲细一点"）、删除、交换位置、改分值（单题 / 整体 / 按题型）、改标题、对多题同时修改、对不存在的题（"第 20 题"）、含糊指令（"改好一点"）、与出题混淆的指令。约 36 例，分 val / test。
3. **整卷蓝图用例** `eval/datasets/edit/papers_spec.yaml`：单元测试 / 期中 / 期末 / 月考，40 / 45 / 80 / 90 分钟，不同总分与题型结构，约 12 例；蓝图的评测是确定性的，不调用写题模型。
4. **追问评测集** `eval/datasets/edit/ask.yaml`：约 20 例（为什么选 B、考什么知识点、怎么做、还有别的解法吗、这道题难在哪、超纲吗），基础试卷同上。

## 3. 指标与阈值（初版；基线后校准，不为过线改定义）

| 指标 | 定义 | 类别 | 阈值 |
|---|---|---|---|
| **C1** | 编辑成功率：①改动体现 ∧ ②无附带破坏 ∧ ③复核通过，三者同时满足的用例占比 | 目标 | ≥ 0.90 |
| C1① / ② / ③ | 分项（定位弱项用） | 诊断 | ② 应为 1.00（确定性保证） |
| **C2** | 手改复核时延：从提交补丁到该题核验状态更新（`item.status` 事件） | 诊断 | p95 ≤ 3s |
| R1 | 撤销 / 重做 / 回退守恒（属性测试） | 硬不变量 | = 1.00 |
| R2 | 复核结果不覆盖用户的新改动 | 硬不变量 | = 1.00 |
| P-A | 蓝图：各题分值之和 = 总分 | 硬不变量 | = 1.00 |
| P-B | 蓝图：题量落在时长对应的合理区间（每 5 分钟 1.5～2.5 题，随题型结构调整） | 目标 | ≥ 0.95 |
| P-C | 蓝图：主要知识点覆盖率 | 目标 | ≥ 0.90 |
| P-D | 蓝图：分区内难度单调不降 | 目标 | = 1.00 |
| S7 | 追问：回答了问题且与题目一致（判官，不同源） | 目标 | ≥ 0.90；与题目答案矛盾 ≤ 0.02 |

## 4. 实现策略（先写下来，实现后对账）

1. **修订模型**：线性历史（`revisions`），每条修订记录 `kind`（edit / undo / redo / restore）、`parent`（它所基于的"逻辑版本"）与重做栈；撤销 = 新增一条恢复上一逻辑版本的修订，**历史只增不删**。diff 由两个快照计算（纯函数），不依赖补丁的写法。
2. **手改复核**：补丁落盘即返回；被改内容的题状态置 `pending`，同时发起一个"复核运行"（走事件流，C2 就是该运行里 `item.status` 的时延）。复核只用不依赖求解程序的检查：结构、盲解、边界、质量；结果在"该题 rev 未变"时才落盘。
3. **自然语言编辑 = 规划 + 执行**：模型只负责把指令译成小词表里的**编辑计划**（改写 / 删除 / 移动 / 改分值 / 改标题 / 只改文字字段）；执行是确定性代码。**改写**复用创作阶段（写题 → 核验 → 修复），把原题与教师要求作为上下文，因此"复核通过"免费获得。目标解析（第几题 / 全部 / 某题型）是确定性的，"附带破坏"由此在结构上被排除（未点名的题不进入执行）。
4. **装配**：在已有试卷上追加是默认；只有明确说"重出 / 换一批 / 全部换"才替换。分值与总分由确定性规则（按题型权重分配、取整、尾差给最后一题）。
5. **组卷分阶段**：蓝图（细目表：分区 × 题型 × 题量 × 分值 × 知识点 × 难度）确定性生成 → 检查点 `blueprint`（确认 / 改要求后重排）→ 样题 2～3 道 → 检查点 `samples`（继续 / 重出样题）→ 全卷。
6. **追问**：只读，上下文 = 目标题（题干、答案、解析、知识点说明）；不改试卷。
7. **特性开关**：`edit.review`（改后复核）、`paper.staged`（检查点）、`paper.coverage`（按知识点覆盖率规划）、`answer.context`（追问带知识点说明）；首轮消融在本里程碑内完成。
