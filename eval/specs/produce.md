# M3b 创作与核验（produce）评测规格

范围：把规划给出的 `ItemSpec` 变成 `Item`——**写题**（题面、选项、答案、解析、求解程序）、**分层核验**（程序求解、盲解、能力边界、题面质量、新颖度）、**修复**，以及 `template` 来源的快速路径。这是产品"可验证"这一承诺的核心，也是北极星指标 A1 与闸门 A2、A3 的来源。设计依据：[D5](../../docs/design.md)、[D9](../../docs/design.md)、[D24](../../docs/design.md)、[architecture §5.1](../../docs/architecture.md)。

## 1. 失败模式与检测手段

下表前 4 行的"证据"来自实现前对通用大模型的**朴素基线探测**（`qwen3.8-max` 一次性"出 N 道题"，6 个请求 / 27 道题，2026-10-05）：

| # | 失败模式 | 证据 / 用户感受 | 检测手段 | 指标 |
|---|---|---|---|---|
| 1 | **答案算错** | 27 道里 4 道最终答案与自己的解析算出的结果不符（如 `69.3` vs `59.3`、`555.2` vs `555.5`）；教师没时间验算 | 求解程序（沙箱）+ 独立盲解两路；审计模型独立复核 | A2 |
| 2 | **答案与解析自相矛盾**：解析里写"等等，重新算…"、答案和解析给出不同结论 | 27 道里 4 道（15%）的解析泄漏了模型的自我修正（"等等，重新算…"），其中 1 道答案与解析的结论相反（答"不够"，解析算出"够"） | 解析一致性（判官逐步复算）；输出清洗规则 | A2、A6 |
| 3 | **在解析里偷偷改题**：发现题目有问题就改数据，题面没改 | 1 道（"把 13.85 改成 28.85"） | 同上；写作时要求"先算后写"（求解程序先行） | A2、A6 |
| 4 | **答案格式不规范**：答案里夹整句话、多问混在一个答案里 | 多道 | 结构化答案（每问一个值）；答案显示由程序拼装，不由模型自由书写 | A6 |
| 5 | **题意歧义 / 条件不足 / 条件矛盾 / 多解** | 学生无法作答，教师难以讲评 | 判官（歧义标记）；构造的缺陷题集上的召回 | A6 |
| 6 | **超纲**：数域、小数位数、运算形态、概念超出目标课时 | 四下出"7 ÷ 2.5"；二年级出分数运算 | 特征抽取 + `check_item`（确定性）；审计用 chalkbase 自带抽取（不同模型、不同提示） | A3 |
| 7 | **数据荒谬**：人数 3.5 个、价格 0.001 元、年龄 150 岁、一把尺长 5 米 | 题目不可信 | 判官 rubric 的"数据合理"项 | A6 |
| 8 | **雷同**：与教材题型示例相似；与用户上传题相似；套内重复 | 没有新意 / 学生做过 | 相似度（字符 n-gram + 数字模式） | A5 |
| 9 | **伪综合**：声称用到两个知识点，解答只用一个 | 综合题名不副实 | 判官核对"每个声称的知识点在解答中的作用" | A5c |
| 10 | **与规格不符**：题型、难度、知识点跑偏 | 要选择题给了填空 | 结构检查（确定性）；难度由判官估计、与目标比较 | A4 |
| 11 | **格式不合法**：TeX 语法错、选择题答案不在选项里、填空位置错、依赖图形却没有图 | 渲染 / 导出错乱 | 规范化 + TeX 语法校验 + 结构检查；本里程碑**不出依赖图形的题**（图形属 M6） | C4 前置 |
| 12 | **验证器漏检**：错题被标"已核验" | 信任崩塌（最严重） | VerifyBank 上的错答检出率；端到端审计里"已核验却错"的数量 | **V1、A2(a)** |
| 13 | **验证器误杀**：好题被拒，浪费成本与时间 | 慢、贵 | VerifyBank 上对正确题的误杀率；废弃 token 占比 | V2、E4 |
| 14 | **修复无效或丢约束**：修好了答案却丢了情境 / 难度 | 反复修仍不对 | 修复成功率；修复后规格符合率 | E4 |
| 15 | **慢、贵**：核验把首题时间拖过上限 | 等待焦虑 | D2 / D3；E1 / E3 | D、E |
| 16 | **`template` 来源的渲染问题**：需要图的题型、`rule` / `human` 类题型、占位符未代入 | 题面残缺 | 题型过滤（只取 `program` 且不依赖图形）；渲染警告为 0 | A2、C4 前置 |

## 2. 评测数据

### 2.1 端到端用例（L3，`eval/datasets/cases/produce.yaml`）

自然语言请求（口吻与 understand 用例一致）→ 理解 → 规划 → 创作，每例带结构化期望（题量、知识点覆盖关键词、档位下限、题型、情境、限制、禁止越界）。按年级 × 领域 × 档位 × 难度 × 来源（`novel` / `template`）× 限制分层，**约 70 例**；val / test 各半；**验收前另补一批新的未见用例**（沿用 M2 的教训，见 eval/CHANGELOG.md）。边缘情形（题量 1 或 10、"数字别太大"、"不要图形题"、指定情境、跨年级复习）各占一定比例，但不钻牛角尖。

### 2.2 核验评测集（L2，直接测验证器，**不依赖写题模型**）

验证器是"可验证"的根基，必须能被**脱离写题质量**单独评测，否则写题模型太好会让验证器看起来无事可做。

- **VerifyBank（答案核验集，约 600 项）**：
  - *正确题（约 250）*：①教材题型实例化（chalkbase 的程序答案，覆盖 1～6 年级、计算 / 填空 / 应用 / 判断 / 选择）；②模型写的题，经**两个不同厂商的审计模型 + 求解程序一致**确认答案正确。
  - *错误题（约 350）*：①**程序化注入**的错误答案（数位滑错、进退位错、小数点移位、运算符号错、漏单位换算、多问题只答一问、答案取了中间结果等，按类型标注）；②**自然错误**：朴素基线里被审计判定答案错的真实题。
  - *缺陷题（约 60，用于题面质量检查的召回）*：对正确题做**构造式破坏**（删掉必要条件、加入矛盾数据、让问法有两种合理理解、数据荒谬），标注由构造得到。
- **BoundaryBank（超纲核验集，约 140 项）**：
  - *数值维度（约 60）*：同一题型在**目标课时**之内 / 之外采样参数（数位、小数位数超限），标签取自 chalkbase 对参数特征的确定性判定（`Problem.boundary`），题面文本是被测输入。
  - *概念 / 运算形态维度（约 80）*：我按课程知识撰写的"目标课时 + 题"（成对：同一情境，一道在范围内，一道含稍后才学的内容，如三年级出方程、四下出小数除法、二年级出分数加法、一年级出两位数乘法）。**标签校验**：每道越界题登记"越界的知识点"，测试用知识库断言该知识点的首次引入课时晚于目标课时，防止标注本身出错。

### 2.3 审计（独立于被测系统的"裁判"）

端到端评测里 A2、A3、A5、A6 不能用线上核验自己的结论打分（循环论证），因此审计走**另一条路**，结果缓存在 `eval/audits/`（随仓库提交，保证回放时确定且无需网络）：

| 指标 | 线上核验路径 | 审计路径（不同模型 / 不同提示 / 不同方法） |
|---|---|---|
| A2 答案正确 | 求解程序 + `solver` 盲解 | 两个不同厂商的思考模型各自**写程序并执行**求解（精确算术），二者与题目答案都一致才判"正确"；一致且不同于题目答案判"错误"；分歧列为"争议"，由我逐条复核并记录（不静默丢弃） |
| A3 不超纲 | 本项目的特征抽取（`extract` 角色）+ `check_item` | chalkbase 自带的 `extract_features`（qwen3.7-plus 思考模式）+ `check_item` |
| A6 / A1 题面 | 在线不用判官，或与审计判官不同 | `judge` 角色，rubric 逐项打分；与我标注的校准集比一致率（κ） |

### 2.4 判官校准集

从 VerifyBank 缺陷题与端到端产出里抽 **60 条**由我按 rubric 标注（1～5 分 + 逐项通过 / 不通过），报告判官与标注的一致率与 Cohen's κ；κ < 0.6 的判官结论只作参考、不得用于闸门（沿用 [evaluation §4](../../docs/evaluation.md)）。

## 3. 指标与阈值（初版；基线后校准，不为过线改定义）

闸门类指标样本量决定能证明多少：要在 95% 置信下证明 ≥ 0.99 需要数百个"已核验"样本，端到端集合给不了。因此验证器的闸门用 **VerifyBank 的检出率**证明（样本量足），端到端只作交叉验证并**如实报告 Wilson 区间与上界**。

| 指标 | 定义 | 验收线 |
|---|---|---|
| **V1 错答检出率** | VerifyBank 错误题里，被核验判为 `fail` / `needs_review`（**不得**判 `verified` / `checked`）的比例；按注入类型切片 | ≥ 0.97（Wilson 下界 ≥ 0.93）；"错题被标已核验"数 = 0 为目标 |
| V2 正确题误杀率 | 正确题被判 `fail`（需修复 / 废弃）的比例 | ≤ 0.08（成本问题而非安全问题，暂定） |
| **V3 超纲检出率** | BoundaryBank 越界题被判 `out` / `borderline` 的比例，按维度切片 | ≥ 0.90（`out` 召回单独报告） |
| V4 范围内误杀率 | 范围内题被判 `out` 的比例 | ≤ 0.10 |
| V5 缺陷题检出 | 缺陷题被题面质量检查标 `fail` / `warn` 的比例 | ≥ 0.80（判官路径，暂定） |
| **A2(a)** 已核验精确率 | 端到端交付题里标"已核验"的题，审计判答案正确的比例 | ≥ 0.99（点估计；同时报告 Wilson 上界） |
| **A2(b)** 全部交付正确率 | 全部交付题（含"已校对"）答案正确的比例 | ≥ 0.97 |
| **A3** 不超纲率 | 交付题经审计抽取 + `check_item`：`out` 的比例 | ≤ 0.02；`borderline` 必带提示 |
| A4 需求满足度 | 结构化期望逐项通过 | ≥ 0.90 |
| A5 新颖度 | (a) 与教材题型示例雷同率 ≤ 0.05；(b) 套内重复 ≤ 0.03；(c) 综合题"真综合"≥ 0.80 | 同左 |
| A6 题面质量 | 判官逐项通过率（题意明确、条件完整、数据合理、适龄、解析成立）每项 ≥ 0.97；**解析与答案一致率 ≥ 0.98**。（定义变更：实现时判官改为逐项布尔判定而非 1～5 分，见 eval/CHANGELOG.md） | 同左 |
| **A1** 可直接使用率 | A2 ∧ A3 ∧ 无歧义且完整 ∧ 数据合理 ∧ 适龄 ∧ 解析成立 ∧（综合题）真综合的合取（审计口径）。同时报告两个口径：**交付题**口径与**按要求题量**口径（丢弃的题算失败，防止靠丢弃难题抬高指标） | 交付题口径 ≥ 0.90；**按要求题量口径 ≥ 0.80**；且显著高于朴素基线 |
| **题量达成率** | 交付题数 / 教师要求的题数（逐用例统计，也报总体）。教师要 5 道只给 4 道不算可交付 | **≥ 0.95**（门槛，按产品可交付标准定，不因当前做不到而放宽） |
| D2 / D3 | 首个已核验题上屏时间；N=5 题全部上屏 | p50 ≤ 25s、p95 ≤ 45s；p50 ≤ 60s、p95 ≤ 100s |
| E1 / E3 / E4 | 单题成本；每道交付题的模型调用数；修复率与废弃 token 占比 | 基线后设上限；调用数 ≤ 6；废弃 token ≤ 0.15 |

动作：A2(a) 或 V1 不达标 → **先查是哪一类注入错误漏掉了**（按类型切片），再查是哪一路核验应该抓住却没抓住，**在核验层修**，不在写作提示里加"请仔细计算"；A3 / V3 不达标 → 先分维度，区分特征抽取漏项（我方）与边界库本身宽松（反馈 chalkbase，根因 `B` / `K`）；A5 / A6 不达标 → 看写作上下文（教材示例过多会"抄"）、温度、规格质量（回到 plan）。

## 4. 基线

1. **B0 朴素直出**：`smart` 模型单次调用"出 N 道题 + 答案 + 解析"，无知识库、无核验（通用大模型的常见用法，即产品要超越的对象）。在端到端用例集上用同一套审计打分，得到 A1、A2、A3、A5、A6 的基线与失败类别分布。
2. **B1 写后不核验**：本项目的规划 + 写作（含求解程序与结构化答案），关闭全部核验。区分"知识库与规划的贡献"和"核验的贡献"。
3. **B2 仅程序核验**：只开求解程序一路（同一模型写的程序，相关性高）。
4. 验证器基线：**单路盲解**（V1 对比两路）、**自洽性**（同一模型重算）。

## 5. 消融清单（进入主路径的同一里程碑内完成）

`produce.program_check`（求解程序）、`produce.blind_solve`（盲解）、`produce.boundary_check`（边界）、`produce.quality_check`（题面质量）、`produce.repair`（修复循环）、`context.textbook_examples`（写作上下文里的教材题型）、`context.contexts`（情境库）、`produce.solution_first`（先写求解程序再写题面 vs 先写题面）；`smart` 能否降为 `fast`；`solver` 用思考模式 vs 非思考 + 程序求解。指标：A1 / A2 / A3 / A5 / A6 / D2 / D3 / E1 的变化与 A/A 噪声参照。

## 6. 模型选型（角色级对比，数据决定）

| 角色 | 候选 | 比较 |
|---|---|---|
| smart（写题） | qwen3.8-max、qwen3.7-plus、deepseek-v4-pro、deepseek-v4.1-flash（思考） | B1 路径下的 A2（写作原始正确率）、A5、A6、A3 前置、延迟与成本 |
| solver（盲解） | 与 smart **不同源**的思考模型：deepseek-v4.1-flash（思考）、deepseek-v4-pro、qwen3.8-max（思考）；方法：直接作答 / 写程序求解 | **VerifyBank 的 V1 / V2**、延迟、成本 |
| extract（特征抽取） | deepseek-v4.1-flash（思考）、qwen3.8-flash、qwen3.7-plus | BoundaryBank 的 V3 / V4、延迟、成本 |
| judge（题面质量） | 与 smart 不同源 | 校准集 κ、V5 |

决策规则：先过闸门指标 → 在延迟约束内选成本最低者；候选与数据写入 design.md。

## 7. 已知局限（预先声明）

1. 审计与线上核验都依赖语言模型，二者独立但不是"人工真值"；争议项由人工复核，规模有限（只保证精确到我能逐条复核的数量）。
2. 教材原题文本不是知识库的公开接口，新颖度的"教材雷同"只与**题型卡片的模板与改写示例**比较（若发现雷同漏检，应向 chalkbase 提需求暴露习题检索接口，根因 `K`）。
3. 本里程碑不出依赖图形的题（几何作图、统计图读取等），这类题的覆盖留给 M6 `figures`；用户要求时明确告知。
4. 写题与核验的模型都来自同一平台（DashScope），模型家族间并非完全独立（qwen 与 deepseek 是不同厂商，但训练数据有重叠）。

## 8. 结果

（验收后补充；中间数据见 [eval/CHANGELOG.md](../CHANGELOG.md) 与 [roadmap.md](../../docs/roadmap.md)。）首次端到端基线（base1，旧配置，36 条 val）：交付题 A1 0.855 对朴素直出 0.724；A2(b) 0.941 对 0.833；A3 超纲 4.6% 对 12.5%；套内重复 14% 对 41%；题量达成率约 0.81（丢弃 19%，其中约一半来自 `template` 路径，已修）；D2 / D3 p50 29s / 58s；单题成本 ¥0.053（旧写题模型，现已降到约 ¥0.011～0.018）。教师偏好盲评（10 个请求）VeriChalk 胜 5 / 平 3 / 负 2，两个负例都是交付不足而非题不好。

## 9. 接续指南（开发者与后续会话读这一节）

**当前分支与状态**：本地分支 `m3-wip`（未推送）。新建的录制缓存目录（`eval/cassettes/` 下除早先的 smoke / understand* / build_para / chalkbase_embeddings 之外的 verify_bank、bake_*、audit、produce、naive_models、scratch_*）**没有提交**：它们是探索产物，验收时再决定提交哪些作为回归基线。

**快速迭代工具（优先用它们，不要整套重跑评测）**
| 目的 | 命令 | 耗时 / 成本 |
|---|---|---|
| 只跑创作阶段、看每次被哪项检查拦下 | `python scripts/probe_produce.py "请求" ["请求"…] [--items] [--off flag] [--role smart=模型:notemp]` | 约 1 分钟，几分钱 |
| 读题（打印交付的题目全文） | 同上加 `--items --quiet` | |
| 一套请求的产出 → JSON，供对比 | `--file eval/datasets/quality_probe.yaml --out x.json` | 3～4 分钟 |
| 两套产出盲评对比（好题） | `python scripts/compare_sets.py a.json b.json` | 约 ¥0.1 |
| 端到端、不审计（交付数 / 延迟 / 成本 / 一次通过率） | `python -m verichalk.eval produce --no-audit --split val --limit 14 --record --cassette-ns scratch_e2e --tag x` | 5～8 分钟 |
| 端到端 + 审计 + 朴素基线 + 教师偏好 | `… produce --naive …`（去掉 `--no-audit`） | 15～30 分钟，里程碑才用 |
| 核验器在 VerifyBank / BoundaryBank 上 | `python -m verichalk.eval verify --bank answers|boundary --role solver=模型:think` | 几分钟 |
| 累计花费 | `python scripts/spend.py` | |

**已验证的设计决策**：见 [design.md D33～D38](../../docs/design.md)。关键事实：①写题 qwen3.7-plus（与 qwen3.8-max 无差别，价格 1/6）；②盲解 / 抽取用 deepseek-v4.1-flash 非思考；③单题 45 秒预算、修复 1 次 + 重写 1 次、丢弃后补题一轮；④`template` 路径要为题生成具体解析（`produce.explain`）并只用主知识点匹配的题型；⑤算式 / 方程答案按值 / 解比较（`verify/expr.py`）。

**踩过的坑**
- bash heredoc 里的 python：反斜杠转义会被折叠（`\\n` 变真换行、`\\times` 变 TAB）。凡含反斜杠的代码 / 提示词，用 Write / Edit 工具写。
- 模型在 JSON 里写 TeX 反斜杠：`extract_json` 会修复，`normalize_text` 还原控制字符。
- 大批量评测慢的真正原因：审计里 chalkbase 自带的思考式特征抽取每题约 1 分钟（并发已调到 20）；探针并行抢并发。
- `tmp/` 必须为空（`test_tmp_is_empty`）；清理时用明确文件名，通配符 `rm tmp/*` 在切目录后会被安全检查拦下；临时输出放会话临时目录，不放仓库 `tmp/`。
- 评测集的已知局限：VerifyBank 区分不了盲解模型（都到天花板）；模板来源的超纲 `in` 标签偏宽；审计判官 / 比较有格式噪声（"3 位数 / 三位数"等，已部分修复）。
