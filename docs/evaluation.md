# 评测方案

> 评测先于实现。每个阶段开工前先在 `eval/specs/<阶段>.md` 写出：失败模式、检测手段、评测数据、阈值与动作、基线；跑出基线后再实现，之后每次改进都要相对基线有可度量的变化。指标定义见 [metrics.md](metrics.md)。

## 1. 三层评测

| 层 | 内容 | 门槛 | 运行 |
|---|---|---|---|
| **L1 不变量** | 分层依赖、事件与 OpenAPI 契约、Patch 应用的可逆性、沙箱隔离、提示词元数据、指标计算的正确性、核验状态汇总规则 | 100% 通过 | 每次提交（`pytest`） |
| **L2 组件评测** | 单个阶段 / 模块对标注数据：意图解析（B1–B3）、拍照转写与映射（B4–B6）、组合挖掘（A5c）、边界特征抽取（A3）、盲解一致率、判官校准、导出保真（C4） | 阶段验收线 | 阶段验收 / 每日 |
| **L3 端到端** | 场景用例集上跑完整管线，计算 A–F 全部指标，含用户模拟的多轮会话 | 里程碑出口标准 | 里程碑验收 |

另有**线上监控**（部署后）：同一套指标函数作用于真实 trace，调试台"指标页"展示。

## 2. 运行方式与可复现

```bash
python -m verichalk.eval run --suite core --split val --mode replay        # 回放已录制的模型响应：确定、零成本，用于回归
python -m verichalk.eval run --suite core --split val --mode live --record # 实调模型并录制
python -m verichalk.eval compare --base <run_id> --new <run_id>            # 两次评测对比（按指标与切片）
```

- 结果写入 `eval/reports/<时间>_<suite>.md` 并追加到 `eval/reports/history.jsonl`；报告含：分层指标 + Wilson 区间、失败样本按根因归类、相对基线与上一版的变化。
- **录制回放（cassette）**：模型调用以 hash(model, 参数, messages) 为键存储；`replay` 下只要提示词与逻辑未变就逐位复现，因此逻辑类改动（编排、检索、核验汇总）可以零成本回归；提示词或模型变了则需要 `live`。
- **val / test 划分**：val 用于开发调参，test 只在阶段 / 里程碑验收时使用；**不允许为了过线修改评测**，评测定义的调整记录在 `eval/CHANGELOG.md` 并用新定义重算历史。

## 3. 评测数据

### 3.1 场景用例集（`eval/datasets/cases/*.yaml`）

自拟，约 160 例，按下列维度**分层构造**（覆盖真实教师会说的话，包括边缘情况，但不钻牛角尖——判据：该情形在真实使用中出现概率约 ≥1%）。

| 维度 | 取值 |
|---|---|
| 场景 | S1 单点 / S2 综合创新 / S3 拍照扩题 / S4 整卷 / S5 复习串联 / S6 修改 / S7 追问 / S8 导出 / S9 异常 |
| 年级 | 1～6（3～5 年级权重更大）；跨年级 |
| 领域 | 数与代数 / 图形与几何 / 统计与概率 / 综合与实践 |
| 明确程度 | 完整；缺年级；缺范围；缺题量；含糊（"出点题"）；互相矛盾（"二年级的方程题"） |
| 档位 / 风格词 | 巩固；变式；综合 / 拔高；场景化；"类似课本" |
| 限制 | 数字大小、不要图形、指定题型、指定情境、只要答案 |
| 多轮 | 追问；局部修改；"再来几道"；"保留第 2 题其他重出"；澄清后继续 |
| 边缘 | 超纲要求；题量极大（50）或极小（1）；口语 / 错别字 / 夹英文 / 带表情；要求教材原题；非小学内容；非数学；提示注入；过长文本；中途取消 |

用例格式：

```yaml
id: c-s1-0042
split: val
tags: [S1, grade4, na, tier:integrated, explicit:partial]
turns:
  - user: "四下学完小数加减了，出4道有点难度的，最好跟买东西有关"
expect:
  brief: {grade: 4, semester: 2, count: 4, difficulty: 4, style.scene: 购物}   # B1
  structure: {items: 4, kp_coverage: [小数加减法], tier_mix: {integrated: ">=1"}}   # A4 的确定性部分
  rubric: [A1, A6]          # 需要判官的部分
  clarify: false            # B2
  forbid: [out_of_bounds]   # A3
```

### 3.2 拍照集（`eval/datasets/photos/`，**不入库**）

练习册照片含教辅版权内容，仅本地存放（`.gitignore` 排除，标注文件同样不入库）。来源：真实拍摄（四年级下册练习册十余张）+ 由真实照片程序化增强出的变体（旋转、透视、模糊、低光、反光、局部遮挡、带手写痕迹），每个变体沿用其源图标注。标注按多模型交叉流程产生，抽样人工复核（见 §4）。

### 3.3 编辑集 / 导出集

- 编辑集：对固定试卷施加 ~60 条自然语言修改（换场景、改题型、改难度、改数字、删题、加题、整体调整），期望含"应改变"与"应保持不变"两部分（C1）。
- 导出集：覆盖公式密集、长题、选项对齐、带图、含表格的试卷，用于 C4 的自动检查（文件可打开、页数合理、无缺字）与人工抽检。

### 3.4 标注数据的生产（沿用 ChalkBase 的方法）

1. 标注规范先行（`eval/annotation/<任务>/guideline.md`：判定标准、边界案例、正反例）。
2. 约 30 条样本跑全部候选模型，校准规范。
3. 至少两个不同厂商的模型独立盲标；分歧由更强模型在思考模式下仲裁；低置信度条目进队列。
4. 报告模型间一致性（Cohen's κ）；从"一致采纳""仲裁采纳"两层分别抽样复核，报告准确率与 Wilson 区间；低于 95% 则修订规范或换模型组合，而不是放宽标准。
5. **独立性**：流水线里的模型不得出现在同一任务的标注模型组中；判官与被评对象不同源。

## 4. 判官（LLM-as-judge）

- 用于 A1、A4（语义部分）、A5c、A6、C1。每个判官有 rubric（逐项判定，不给笼统总分）、结构化输出（项目 + 证据 + 结论）、固定温度。
- **校准**：每个判官配一份标注校准集，报告与标注的一致率与 κ；κ < 0.6 的判官结论只作参考，且不得用于闸门。
- **位置与长度偏差检查**：成对比较时随机交换顺序；长度与得分的相关性作为判官健康指标。
- 判官提示词与 rubric 版本化，版本变化必须重跑校准。

## 5. 模型选型评测（角色级对比）

模型选择是配置而不是代码，且应由数据决定。对每个角色在同一批输入上对比候选：

| 角色 | 候选（初始） | 比较指标 |
|---|---|---|
| fast | qwen3.8-flash、deepseek-v4.1-flash、qwen3.7-flash | B1–B3、E5、D5、E1 |
| smart | qwen3.8-max、qwen3.7-plus、deepseek-v4.1-flash（思考）、deepseek-v4-pro | A1–A6、D5、E1 |
| vision | qwen3.8-flash（多模态）、qwen3-vl-plus、qwen3-vl-flash、qwen3.8-omni-flash、qwen-vl-ocr | B4、B5、D5、E1 |
| solver（盲解） | 与 smart 不同源的思考模型 | A2（一致率与误杀）、E1 |
| judge | 与被评对象不同源 | 判官校准 κ |

决策规则：先过闸门（A2、A3、B 类下限）→ 在延迟约束内选成本最低者 → 结果与候选表写入 [design.md](design.md)。国内 / 新加坡 profile 的延迟差异单独记录，部署用新加坡 profile。

## 6. Badcase 闭环（FR-12）

```
发现（调试台 / 评测失败 / 线上）→ 入库（eval/badcases/*.yaml）→ 归因 → 在对应层修复 → 回归 → 关闭
```

Badcase 记录：`id`、来源（run_id 或评测用例）、输入、观察到的问题、期望、**根因类别**、严重度（S1 致命：答案错 / 超纲 / 崩溃；S2 明显：不符需求、体验差；S3 轻微）、涉及阶段、状态、修复提交、对应回归用例。

**根因类别**（决定修在哪一层）：

| 代码 | 类别 | 典型修复位置 |
|---|---|---|
| U | 理解：误解 / 漏字段 / 该问没问 / 过度澄清 | `understand` 提示与评测集 |
| P | 感知：转写错 / 映射错 / 误把手写当题面 | `perceive`、预处理 |
| R | 规划：范围错 / 组合不自然 / 覆盖不全 | `knowledge`、`ComboMiner`、`plan` |
| W | 生成：歧义 / 数据荒谬 / 不新颖 / 难度偏离 | `produce.write` 提示与上下文 |
| V | 核验：漏检（坏题放行）/ 误杀（好题被拒） | `verify` 检查本身 |
| B | 边界：特征抽取漏项 / 边界库本身宽松 | 特征抽取；**上游反馈到 chalkbase** |
| E | 编辑：没改到 / 附带破坏 | `edit` |
| X | 导出：公式 / 版面 | `render` |
| S | 系统：超时 / 限流 / 崩溃 / 缓存失效 | 网关、编排 |
| K | 知识库数据问题 | 向 chalkbase 提 issue |
| UX | 交互 / 文案 / 进度提示 | 前端 |

修复纪律（D24）：在根因所在层修；修复合入时必须附：①新增的回归用例 ②受影响指标前后对比（有变好、无变坏）。

## 9. 消融实验（拒绝盲目堆砌复杂度）

**原则**：Agent 里每一个会增加延迟、成本或代码复杂度的模块，都必须用消融实验证明自己值得存在。

- **可关闭**：每个模块（提示词策略、检索环节、核验检查、预热、修复循环等）在 `core/features.py` 注册为一个**特性开关**（名称、说明、默认开）；关闭后系统必须仍能运行（降级到更简单的做法）。
- **运行方式**：`python -m verichalk.eval run --suite core --off <flag>[,<flag>]`；`python -m verichalk.eval ablate --suite core --flags a,b,c` 依次跑"全开"与"逐项关闭"，输出对照表（北极星、闸门、延迟、成本、缓存命中的变化及置信区间）。报告头部会写明被关闭的开关。
- **噪声控制**：每次消融先跑一遍丢弃的预热轮（消除进程级一次性初始化造成的顺序假象），并自动加入一行 **A/A 噪声参照**（同一配置重复运行）；变体与全开的差异必须明显大于 A/A 的差异才可信。
- **判定**：关闭后若**质量指标无显著下降**（置信区间包含 0），且延迟或成本更优，则该模块**应当删除**；若质量下降但代价过高，需要记录权衡。结论写入 [design.md](design.md)（`D<n>`），附实验报告路径。
- **何时做**：模块进入主路径的同一个里程碑内完成首轮消融；之后每次大改（模型、提示词）重跑受影响模块的消融。
- **范围**：不仅是"功能开关"，也包括——提示词里各段内容（教材示例、边界约束、情境）、检索的各路信号（词法 / 向量 / 图扩展 / 跨点共现）、核验的各路检查（盲解、特征抽取、相似度）、修复循环次数、模型档位（smart → fast 能否降级）。
- **初版清单**（随实现补全）：`warmup`（预热）、`retrieval.dense`、`plan.combo_miner`、`produce.blind_solve`、`produce.boundary_check`、`produce.novelty_check`、`produce.repair`、`context.textbook_examples`。
