# M8 对外版本：端到端评测规格（test 划分）与发布门槛

范围：对外版本（首个可部署版本）的验收——**整个产品**在 test 划分上的端到端表现，对照 [evaluation.md §7](../../docs/evaluation.md) 的发布门槛逐项给出"达标 / 未达标 / 证据在哪"。本文件不新增指标，只汇总各里程碑的 test 划分结果，并补上此前没有证据的几项闸门（F5 恢复能力、G1 提示注入）。

## 1. 失败模式与检测手段

| # | 失败模式 | 检测手段 | 指标 |
|---|---|---|---|
| 1 | 题目答案错、却标"已核验" | 审计：独立程序求解 + 盲解（与流水线不同源的模型）对每道交付题复核 | A2（闸门） |
| 2 | 交付超纲题 | 审计：chalkbase 的能力边界判定（特征抽取 + 课时级边界） | A3（闸门） |
| 3 | 题目"能直接用"的比例不如直接问模型 | 与朴素直出（同一个 smart 模型一次性生成、无核验）在**同一批用例**上对比 | A1（北极星）相对基线 |
| 4 | 运行崩溃 / 没有可理解的结果 | 全部评测运行的状态与事件完整性 | F1（闸门） |
| 5 | 事件日志缺失 / 孤儿 span | 每个运行的 span 树完整性（确定性） | F6（闸门） |
| 6 | 服务重启后会话、试卷、事件丢失，或被打断的运行把流挂住 | 磁盘数据库 + 新实例重启的集成测试（`tests/test_recovery.py`）；SSE 断线续传（`tests/test_api.py`） | F5（闸门） |
| 7 | 文本 / 图片里夹带指令劫持行为或泄露提示词 / 密钥 | 注入评测集（8 例：5 条文本、2 张含指令的图片、1 条夹带的出题请求），确定性泄露检测 + 行为检查 | G1（闸门） |
| 8 | 导出的文件打不开 / 公式错乱 | 导出评测：14 份试卷 × 4 格式 × 2 版本，LaTeX 实际编译；人工看页面 | C4（闸门） |
| 9 | 理解、编辑、追问、整卷、拍照各自退化 | 各阶段评测的 test 划分（见 §3） | B1～B3、C1、S7、P-A～P-D、B4～B6 |
| 10 | S1 级 badcase 未清零 | `eval/badcases/` 里严重度 S1 的条目逐条核对 | 发布门槛 |

## 2. 评测数据

- **出题端到端**：`eval/datasets/cases/produce.yaml` 的 **test 划分 36 例**（一至六年级、单点 / 综合 / 模板 / 题型限制 / 情境 / 数字限制等；用例的期望在运行前已写好，不是事后标注）。
- **朴素基线**：同一批用例，同一个 smart 模型一次直出，无规划、无核验、无修复。
- **审计**：每道交付题由独立的程序求解 + 盲解复核答案、由 chalkbase 判定是否超纲、由与写题模型不同源的判官评题面质量与意图满足；审计不依赖流水线自己的核验结果。
- **其余阶段**：understand / understand_para 的 test 划分（B1～B3）；edit 的 test 划分（C1）与追问（S7）；整卷蓝图（P-A～P-D，确定性）；导出（C4，确定性）；拍照识别（开发集 + 未见页，见 [perceive.md](perceive.md)）。
- **G1 注入集**：`eval/datasets/injection/`（`cases.yaml` + 两张合成图片，无版权）。
- **留出集**：`produce_fresh`（36 例，从未用于调优）**本次不用**——它是 M3 质量优化之后的验收集，现在用掉就没有了。understand_fresh 与 edit 的 fresh 集同理（已按各自规格使用过一次的除外）。

## 3. 指标与阈值（沿用 metrics.md，不为过线改定义）

闸门：A2(a) ≥ 0.99 且 (b) 报告；A3 `out` ≤ 0.02；F1 ≥ 0.99；C4 成功率 ≥ 0.99、错乱率 ≤ 0.02；F5 = 100%；F6 孤儿 / 缺失 = 0；G1 = 100%。
北极星：A1 相对朴素基线有可度量的提升。目标与护栏（题量达成率、A4～A6、D2 / D3、E1、E3）一并报告，但**不是 M8 的硬门槛**；M3 的既有门槛（题量达成率 ≥ 0.95 等）按 [produce.md](produce.md) 的口径单独列出。

## 4. 实现策略

1. 先补证据缺口：F5（磁盘库重启测试）与 G1（注入评测）此前只有零散的单元测试，没有端到端证据——先补，再跑 test 划分。
2. test 划分**只在这里跑一次**：出题 + 审计 + 朴素基线一次完成；其余套件各跑一次 test 划分；据结果改动系统之后，这些 test 划分不再是干净的留出集（沿用 CHANGELOG 的规则）。
3. 报告随版本发布：本文件 §5 与 `eval/reports/release_m8.md`（汇总表）。

### 5.4 已知问题（审计发现，未修复）

- **答案**：36 例里确认错 1 道（"积应有几位小数"——按"积的末尾 0 是否去掉"有两种读法，题面有歧义；手算 `2.45×1.6=3.920`，按算式规则是 3 位、按化简后是 2 位）。审计分歧 7 道：核对了其中一道（`(120+135+128+137)÷4`）——题目答案 130 是对的，是审计一路求解出错；其余几道（含选择题答案字母与盲解不一致的）未逐一核对，**不能据此认为 7 道都是审计错**。
- **超纲**：7 道，审计依据课时级能力边界；其中几道触及"单价数量总价""两位数加两位数口算"等低年级内容用在了更高年级的情境里，以及"圆锥容积""去掉最高分最低分求平均"。属于 chalkbase 边界与特征抽取的已知局限（M3 记录），**没有在 Agent 里绕过**（工作区约定 3）。
- **没有逐条入库为 badcase**：本期评测只产出审计清单。下一轮 M3 开始时应把这 8 道（确认错 + 超纲）按根因 `W` / `B` 入库再修。
