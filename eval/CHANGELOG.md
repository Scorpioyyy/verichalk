# 评测变更记录

评测定义与评测数据的每一次调整都记在这里：改了什么、为什么、对历史结果的影响。原则：**不允许为了过线修改评测**；修正标注错误、补充区分度不足的用例是允许的，但必须在使用 test 划分验收之前完成，并用新定义重算历史版本。

## 2026-10-05　意图理解（M2）

1. **指标 B1 的定义细化**：metrics.md 原定义为"字段级 F1"。实现时发现期望是"部分标注"（只写有把握的字段），精确率没有可靠的分母，改为：**字段通过率**（写出的字段检查通过的比例）+ **幻觉率**（`absent` 字段被断言的比例）+ **来源准确率**（`user_fields` 中带 `origin=user` 的比例）三项，覆盖原 F1 想衡量的两面（漏解析 / 凭空断言）。基线与模型版都用新定义，没有历史结果受影响。
2. **标注错误修正（基线已跑过一次之后、test 划分使用之前）**：错误分析发现用例生成时期望键 `scenes_any` / `constraints_any` 与"不应断言"列表里的 `scenes` / `constraints` 对不上，导致 13 个有情境 / 限制的用例被错误地要求"不得断言情境 / 限制"；`u-e07` 的题型期望把"两步计算题"标成了应用题（应为计算题）并多写了 `absent: topics`；`u-l17`（提示注入夹带初中内容）期望改为 `offtopic`（用户最终意图是初中内容，且这是注入用例，拒绝是安全且合理的）。修正后用新标注重算了规则基线与模型版。
3. **评测集区分度不足**：规则基线与模型版在作者撰写的 val 集上 B1 几乎持平（0.945 vs 0.963，置信区间大幅重叠）。原因是用例由规则的作者撰写，说法偏规整（作者偏差）。处理：增加由**不同厂商模型改写**的"换说法"用例集（`understand_para`），保持意图不变、说法更口语 / 省略 / 语序多样，并经两个模型核验"意图未变"后才入集。few-shot 示例与评测集的说法保持不重合。

4. **test 划分的使用记录（M2 验收）**：第一次验收（提示词 v2）后查看了失败样本并做了通用修复，因此 `understand` / `understand_para` 的 test 划分**不再是干净的留出集**；文档里相应的数字标注为"事后修复"。为此新增 `understand_fresh`（42 例，全部是新写的说法与主题，重点是小学 / 初中内容的边界、跨年级主题、范围冲突、不同口吻），它在修复之后才第一次被系统看到。**规则：每次据 test 失败样本改动系统后，验收前必须补一批新的未见用例。**
5. **标注规范补充**（`eval/annotation/understand/guideline.md` §7）：①"同类 / 类似 / 照着类型再出"表达的是档位（consolidate），不是 `source: template`；②"口算 / 计算 / 竖式"是题型不是主题；③"串起来 / 放一块儿 / 结合"都表示 integrated。均来自模型与标注分歧的错误分析，不改变已有用例的期望（已有用例的期望本就符合这些解释）。
6. **换说法集的清理**：改写模型对原话 `。。。` 等无意义输入"脑补"出带 `××` 占位符的模板，已剔除这类改写，并在构建脚本里加入过滤（无汉字 / 过短的原话不改写；含 `××` 的改写丢弃）。
7. **录制的更新**：消融实验使用实录模式（按温度 0.3 重新调用模型并覆盖录制），因此每次消融后回放数字会有细微变化（约 ±1～3 个字段检查）。文档里的最终数字取自最后一次回放。

## 2026-10-05　生成与核验（M3）

1. **A6 的定义细化**：metrics.md 原定"判官 1～5 分 + 歧义率"。实现时判官改为**逐项布尔判定**（题意明确、条件完整、数据合理、适龄、解析成立）并给出问题清单：逐项判定比笼统打分更可校准、可归因。报告里 A6 是每一项的通过率。无历史结果受影响。
2. **新增"题量达成率"与"按要求题量的 A1"**：首次基线（base1）显示，丢弃的题让"交付题口径"的 A1 好看（0.855）而"按要求题量口径"低于朴素基线（0.677 对 0.724）。可交付的标准是"教师要几道给几道"，所以两个口径都作为门槛报告，并新增题量达成率 ≥ 0.95。门槛按产品可交付标准定，不因当前做不到而放宽。
3. **核验评测集的修正**：VerifyBank 评测时忽略版式（填空题按计算题处理）、剔除依赖图形的题面（"看图""如图"），否则版式检查先失败会让盲解被跳过，造成虚假的"漏检"；BoundaryBank 的一道手写范围内题（"每盘放 3 个苹果，放了 2 盘"，用到"几个几相加"，在二上才学）标注有误，已换成"盘子里有 3 个苹果，又拿来 2 个"。**使用 test 划分之前**完成。

## 2026-11-04　M3 质量优化：教师视角评审（北极星代理）

1. **为什么新增**：审计里的 A1 判据是"答案对 ∧ 不超纲 ∧ 题面质量逐项通过"，判官**看不到教师的要求**、逐题评而不看整套。读 classic 链路在 `quality_probe` 上的 39 道交付题时发现，它漏掉了教师最在意的几类问题：不符合要求（要"乘法和周长结合"却只考乘法）、把互不相关的小问拼成一道"综合题"、同套题雷同、数据荒谬（4.25 千米/时的公交车）。这些题在 A1 下都算"可直接使用"。
2. **新代理**：`verichalk.eval.teacher_judge`（`scripts/judge_sets.py`）：带着教师原话、一次看整套题，逐题给 good / ok / bad 与问题代码；指标是**可用题数 / 要求题数**（丢弃算失败）。评审模型 deepseek-v4-pro（与写题模型不同厂商）。
3. **校准**：`eval/annotation/teacher_accept/calibration.yaml`（39 道，Claude 按教师视角逐题标注，在判官看到之前完成）。首轮可用与否一致 0.69（κ 0.38），分歧主要来自"什么算不符合要求"双方都没定清楚；补充细则 v2（写在标注文件头部）后，判官提示与标注按同一细则修订（4 道标注改标并注明），二轮一致 0.87（κ 0.74）。已知偏差：判官偏爱判"太难"（3 处）。**它只用于迭代比较；关键结论仍要读题确认。**
4. 原有 A1 / A2 / A3 定义不变。
5. **端到端出题评测的模型并发**（`python -m verichalk.eval produce`）：原为"用例并发 × 2"（默认 8）。4 个用例同时跑、每例 4 道题并行、每题最多 3 个检查并行，峰值约 48 个调用；不够时题目排队、被 45 秒单题预算截断而丢弃。M8 的题量达成率 0.775 主要由此造成（同一 classic 链路在并发充足时交付 0.97～1.0）。改为"用例并发 × 12"。**历史结果未重算**（需要实调重跑）；此前所有"题量达成率"与时延数字都偏悲观，比较时只与同并发条件的结果比。

2. **计分修正：补上的题计入交付**（`eval/produce_eval.py`）。题被丢弃后系统会立刻"换个考法补一道"，补题的结果存在运行状态的 `produce:{题位}r` 下；计分只读原题位，于是**补上的题从没被计入交付、也没有进入审计与评审**，而教师在线上是看得到它们的。自补题机制加入以来的所有出题评测都**低估了题量达成率**、"按要求题数"的指标也随之偏低。同一批开发集请求、同一份旧版代码，修正前交付 0.78、修正后 0.951。用修正后的计分重放上一轮留出集验收的录制，结果见 `specs/produce.md §8.1` 的更正。
3. **教师视角评审的两处口径**（`eval/teacher_judge.py`，对所有被评对象同样适用；本轮的对比都用新口径重评）：
   - 一套题比要求少时，评审会把交付了的题也判为"不符合要求（题量不足）"——题量已经体现在分母里，这是重复扣分。改为"只评每道题本身"。
   - 老师要口算 / 计算题 / 同类题时，评审把"同一类算式换数字"判为雷同；这正是老师要的。改为"用的数完全相同才算雷同"。
4. **课本式题型的超纲**改走正常的抽取 + 判定（此前直接采信知识库按参数给的"不超纲"，偏宽：四下的解方程出现了除数是小数的一步）；知识库判"超纲"的仍直接不用。
5. 评测相关的提示词：`verify.extract` v2（钟面上的数与时刻不计入整数范围）、`plan.compose` v2、`produce.write` v8（新增图形类型）。审计用 chalkbase 自带的抽取器，不受 `verify.extract` 变更影响（因此审计仍会把钟面上的 12 判为一年级上册超纲，见 `eval/badcases/`）。

## 2026-11-07　v1 发布前：目标值校准与留出集换新

1. **目标值校准**（产品负责人决定；在最终验收之前写定，不看结果改线）。初版目标是开工前定的，第一次发布验收后按"产品上可接受"重新校准（`docs/metrics.md`、`specs/produce.md §3`）：A1 按要求题数 ≥ 0.75、交付题 ≥ 0.85（且高于朴素直出）；A2(a) ≥ 0.97、A2(b) ≥ 0.95；A3 超纲 ≤ 0.05；A4 ≥ 0.85；题量达成率 ≥ 0.90；D2 p95 ≤ 60s；D3 p50 ≤ 90s、p95 ≤ 180s；E1 出题单题 ≤ ¥0.05，E3 每道交付题调用数 ≤ 10。A5(b) 套内重复改为诊断：它用字符相似度，同类口算（"28+35""47+26"）天然相似，真正的雷同由教师视角评审判定。指标**定义**都不变。
2. **留出集换新**：第一次发布验收已读过留出集的失败样本，它改作开发数据（`produce.yaml` 的 `pa-*`，开发集共 89 例）。新的 `produce_holdout.yaml`（41 例）逐例镜像它的分层（年级、领域、只用配图题考的主题、请求形式），只换主题与措辞，两份同分布，验收数字可以直接比较；在任何后续改动之前撰写并提交（commit `7342d64`）。
3. **答案比较的文字写法差异**（`verify/answers.py`，线上盲解与审计共用）："红"与"红色"、"三"与"星期三"、"积木"与"一盒积木"视为相同，含否定词的不在此列。第一次发布验收的 6 道"争议"里有 4 道就是这种写法差异（人工复核均为题目正确）。最终验收的四方都在这条规则下审计，口径一致。
4. **跨版本对比**：`python -m verichalk.eval produce` 新增 `--save`（保存原始运行）、`--load`（读回只审计与打分）、`--teacher`（加跑教师视角评审，报告"审计 A1 ∧ 教师视角可用"的按要求题数口径）。main 与上一版 m3-exp 在各自的临时工作区里生成并保存，打上的只有两处评测补丁（补题计入交付、模型并发给够；main 另需经环境代理出网），系统代码不动；三方与朴素直出用同一套审计与评审计分。
5. **审计看得到图的描述**（`eval/produce_eval.py`）：审计模型此前只拿到题面文字，"如图"所指的图对它们是空白，看图题被两路审计一致答成"无法确定"，判为"答错"或"争议"。现在与线上核验一样，读由图形规格生成的文字描述。不带图的题审计键不变、结论不变；带图的题重新审计。最终验收的三个系统都按修正后的审计计分；朴素直出不出图，不受影响。
