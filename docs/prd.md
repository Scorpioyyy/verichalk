# VeriChalk 产品需求文档（PRD）

> 状态：v0.1（M0 收敛稿）。需求以编号（`US-` 用户故事、`FR-` 功能需求、`NFR-` 非功能需求）引用；验收指标见 [metrics.md](metrics.md)，架构见 [architecture.md](architecture.md)，决策见 [design.md](design.md)。

## 1. 产品定位

**VeriChalk 是面向小学数学教师的命题助手：用一句话或一张练习册照片说清需求，在几十秒内拿到答案可靠、不超纲、有新意、能直接用的题目或整份试卷，并能在线微调、一键导出。**

它建立在课程知识库 [ChalkBase](https://github.com/Scorpioyyy/chalkbase) 之上（北师大版 1～6 年级 12 册：知识图谱、题型卡片、能力边界、情境库）。知识库回答"学什么、学到哪、能不能考"，VeriChalk 负责把教师的意图变成一份可交付的题目。

### 1.1 用户痛点（来自对一线小学数学教师的访谈）

教师已经在用通用大模型出题，访谈反复指向两个核心痛点：

1. **正确性**：答案经常算错，学生照抄错误答案。教师没有时间逐题自己验算，只能选择不信任。
2. **意图对齐**：大模型出的题"它觉得重要的不是我觉得重要的"。教师真正想要的是：
   - 同一知识点的**多种题型变式**；
   - **贴近生活**的情境；
   - **跨单元综合**；
   - 把以前学过的内容**穿插进来复习**。

此外还有两个由此衍生的现实问题：通用模型不知道**学生学到哪一课**，题目容易超纲（例如四年级下册只学小数乘法，小数除法在更高年级，却出了"7 ÷ 2.5"的方程）；以及**排版与导出**要手工整理，公式在 Word 里尤其费时间。

### 1.2 与"直接问通用大模型"的差异（产品存在的理由）

| 痛点 | 通用大模型的表现 | VeriChalk 的做法 |
|---|---|---|
| 正确性 | 答案算错，且没有任何提示 | 每道题经程序求解与独立盲解两路核验，界面如实标注核验状态；`rejected` 的题不展示 |
| 不知道学到哪 | 超纲（三年级出方程、四下出小数除法） | 用知识库的课时级能力边界约束并校验每道题 |
| 题型单一 / 抄教材 | 题目千篇一律，或只会改写教材原题 | 把教材题当作"学生学过什么"的上下文，创作新情境、新结构的题，提供巩固 / 变式 / 综合三种档位 |
| 跨单元综合、复习穿插 | 不知道知识点之间的关系，凭感觉拼凑 | 基于知识图谱的前置 / 递进 / 相关关系检索，保证组合在已学范围内且自然 |
| 排版与导出 | 公式排版差，导出要手工整理 | 公式与版面一等公民，在线编辑，导出 PDF / Word / Markdown / LaTeX |
| 长任务黑盒等待 | 一次性输出，不符合要求只能重来 | 全程可见的进度；整卷先出蓝图和样题，确认后再成卷 |

## 2. 用户与场景

**主要用户：一线小学数学教师**。熟悉教材，不熟悉技术，时间紧；日常要出课后作业、随堂小测、单元测试、周末拓展、期末复习。痛点：练习册题目重复、不贴合本班进度；自己编新题耗时且怕算错、怕超纲；Word 里排公式费时间。

**次要用户：家长、校外辅导者**。想给孩子补充练习，往往说不清学到哪一课，需要系统帮助确定范围。

| 编号 | 场景（用户原话示例） | 说明 |
|---|---|---|
| S1 单点出题 | "四年级下册小数加减法，出 5 道，有点难度" | 最常见，范围与数量明确 |
| S2 创新 / 综合 | "出 3 道超市购物情境、要用到小数和统计图的综合题" | 跨知识点，图检索串联 |
| S3 拍照扩题 | 上传练习册一页 +"照这页再出 5 道，再来 2 道拔高的" | 照片是"学生学了什么、做了什么"的上下文 |
| S4 整卷 | "出一份四下第三单元的单元测试，45 分钟，满分 100" | 长任务，分阶段 |
| S5 复习串联 | "期末复习，把乘法分配律和简便运算串起来" | 螺旋复习，前置链 |
| S6 修改 | "第 3 题太简单了" /"换个场景" /"数字别太大" /"改成选择题" | 自然语言编辑 |
| S7 追问 | "第 2 题的解析再讲细一点" | 针对已有题目的问答 |
| S8 导出 | "导出成 Word" | 版式即交付物 |
| S9 异常输入 | 需求含糊、越界（初中内容）、照片模糊、与数学无关 | 要体面地处理，不能崩、不能乱出 |

> 评测用例按这些场景加边缘情况分层设计，见 [evaluation.md](evaluation.md) §3。

## 3. 产品原则（所有设计取舍的裁决依据）

1. **说老师的话。** 界面和对话里不出现"知识点 ID""边界""archetype"这类内部概念；展示为"涉及：小数加减法（四下·第一单元）"。
2. **先给看得见的结果。** 逐题流式呈现；第一道题通过核验就先展示，不等全部完成。任何超过 3 秒的等待都有进度说明。
3. **默认创新，意图优先。**（见 §4）
4. **可信，且诚实。** 答案核验过才标"已核验"；没核验、核验不一致、可能超纲，都明说，不粉饰。
5. **少打断。** 能合理假设就先做，并把假设亮出来让用户一键改；只有不问就大概率做错时才提问，且一次最多一个问题，带可点选项。
6. **一切可改。** 每处内容既能手动改，也能一句话让 Agent 改；改后自动复核。
7. **长任务分阶段。** 整卷类任务先出蓝图和样题，确认后再成卷，避免一次性等很久却不是想要的。
8. **尊重版权与隐私。** 上传图片只用于本次会话；不向用户原样展示教材原题；调试数据只对开发者可见。

## 4. 出题的"先验"：知识库是上下文，不是模板

知识库的题型卡片来自教材原题归纳。**Agent 的先验是把这些内容当作"学生学过什么、做过什么、难度与表达风格是什么"的上下文，创作新题；而不是在教材原题上改数字。**

### 4.1 档位（tier）与来源（source）

| 档位 | 含义 | 典型触发 |
|---|---|---|
| 巩固 | 同一知识点，新数据、新情境 | "出几道练习""巩固一下" |
| 变式 | 同一知识点，条件 / 问法 / 结构变化 | "变式题""换个问法" |
| 综合 | 串联 ≥2 个知识点，在一个情境里自然交织（**图检索为核心**） | "综合题""拔高""应用""串起来" |

难度（1～5）是独立维度，与档位正交。照片扩题（S3）默认混合档位（巩固：变式：综合 ≈ 4:4:2），以可点选的方式调整。

| 来源 | 含义 | 何时使用 |
|---|---|---|
| `novel`（默认） | 模型依据知识上下文创作，经多重核验 | 绝大多数请求 |
| `template` | 题型卡片实例化，答案由程序算出，天然可核验 | 用户明确要"基础计算 / 口算卡 / 同类题批量"，或作为核验与对照基线 |

### 4.2 意图优先规则

- Brief（结构化需求）中每个字段带来源标记：`user`（用户明说）> `inferred`（从上下文推断）> `default`（系统默认）。
- 先验（默认创新）只作用于 `default` 与 `inferred` 的字段；**用户明说的永远覆盖先验**。用户说"就要课本上那种类型的基础题"，就走 `template`、巩固档。
- 无论哪种来源，都必须满足：不超纲、答案核验、不与用户上传的题或教材原题雷同（`template` 来源的"同类题"除外，因为这是用户明确要求）。

## 5. 功能需求

优先级：**P0** 首个对外版本必须；**P1** 紧随其后；**P2** 择机。验收标准里的指标编号见 [metrics.md](metrics.md)。

### FR-1 对话出题（P0）

用户用自然语言提出需求，系统解析为 Brief，检索知识，生成并核验题目，逐题返回。

- 解析年级 / 学期 / 单元 / 课时 / 知识点范围、题量、难度、题型（选择、填空、计算、判断、应用）、档位、风格（情境）、其他限制（如"数字不要太大""不要出图形题"）。
- 范围未说明时按 §6 的澄清策略处理。
- **AC**：意图解析字段级 F1 ≥ 0.90（B1）；意图满足度 ≥ 90%（A4）；首题上屏 p50 ≤ 25s（D2）。

### FR-2 拍照出题（P0）

用户上传 1～4 张练习册 / 作业 / 试卷照片，可附一句话要求。

- 识别每道题的题号、题面（含公式）、是否带图及图的文字描述、学生手写作答痕迹（忽略不当作题面）。
- 把题映射到知识点与大致课时，估计难度与题型分布，形成"学生上下文"；以此约束生成，并把这些题作为**防雷同集合**。
- 识别结果以卡片展示，用户可就地修改；识别置信度低时主动提示（"第 3 题的数字看不清，已按 3.6 处理，点这里改"）。
- **AC**：题目转写准确率（B4）、知识点映射 top-3 命中（B5）达到 [metrics.md](metrics.md) 目标；非数学 / 超出小学范围 / 模糊图片给出友好反馈，不乱出题。

### FR-3 澄清与假设（P0）

- 只在缺失信息会导致大概率做错时提问（如完全没有年级与范围）；一次最多问一个，给 2～4 个可点选项，并允许"你来定"。
- 其余情况先按假设执行，并在结果顶部显示"本次假设"芯片（年级、范围、题量、难度、档位），可一键调整并重出。
- **AC**：该问时问、不该问时不问（B2：澄清精确率 ≥ 0.85，召回 ≥ 0.80）；澄清轮次占比 ≤ 15%。

### FR-4 组卷（P1）

- 输入：范围、题量或时长 / 总分、题型比例、难度分布。
- **分阶段**：①蓝图（题型 × 知识点 × 难度 × 分值的细目表，可编辑）→ ②样题（先出 2～3 道让用户判断风格）→ ③全卷生成 → ④排版（分卷题序、分值、答案与解析附页）。每一步都可调整后继续。
- 蓝图保证覆盖度（所选范围内的主要知识点都有题）、难度梯度、题型搭配、无重复考点堆叠。
- **AC**：蓝图在 20s 内（p50）返回；全卷分数合计、题号连续、覆盖率（A4 的子项）全部通过结构检查。

### FR-5 题目质量与核验标注（P0）

- 每道题带核验状态：`已核验`（程序求解与独立求解一致）、`已校对`（单路核验通过）、`需复核`（存在疑点，附原因）。`rejected` 的题不展示（系统自动修复或重出）。
- 超纲提示：`borderline`（本单元稍后才引入）以柔和提示呈现，`out` 不展示。
- 题目质量：题意明确、答案唯一、语言适龄、情境真实合理、不与已有题雷同。
- **AC**：标"已核验"的题答案正确率 ≥ 99%（A2，闸门）；不超纲率 ≥ 98%（A3，闸门）；可直接使用率（A1，北极星）达标。

### FR-6 编辑（P0）

- **手动**：在预览上直接编辑题干、选项、答案、解析、分值；公式有源码编辑 + 实时预览；增删、拖拽排序、换题型。
- **自然语言**：针对某题或整卷下指令（"第 3 题换个场景""整体降一点难度""把选择题改成填空"）。Agent 输出结构化修改（Patch），应用后自动复核，并显示 diff；可撤销 / 重做。
- **AC**：自然语言编辑成功率 ≥ 90% 且无附带破坏（C1）；手动修改后的复核在 3s 内给出状态（C2）。

### FR-7 预览与排版（P0）

- 数学公式用 TeX 渲染（前端 KaTeX），排版接近真实试卷：大题分区、题号、横线填空、选择题选项对齐、插图、表格。
- 默认**工作台视图**（卡片式，便于操作）与**试卷视图**（所见即所得的分页预览）可切换。
- 教师版（含答案与解析）/ 学生版（空白）一键切换。

### FR-8 导出（P0：PDF、Word；P1：Markdown、LaTeX）

- PDF（含中文字体、公式、插图）、Word（公式为原生公式对象，可继续在 Word 里编辑）、Markdown、LaTeX 源码。
- 导出选项：教师版 / 学生版、是否含解析、是否含答案页、页眉（学校 / 班级 / 姓名 / 日期）。
- **AC**：导出成功率 ≥ 99%（闸门）；导出文件人工抽检公式、版面无错乱。

### FR-9 过程可见（P0）

- 用教师能懂的话报告进度："正在理解需求 → 回顾四下前三单元学过的内容 → 构思题目 → 逐题核验（2/5）"。
- 逐题上屏，核验状态在题上实时更新；可随时"停止"；失败时说明原因并给出重试选项。
- **AC**：首个可见反馈 ≤ 1s（D1）；长任务全程无超过 5s 的静默（事件间隔）。

### FR-10 会话与历史（P1）

- 匿名会话（无账号），浏览器本地保存会话标识；会话内保留消息、试卷、版本历史；可回到某个版本。
- 同一会话多轮修订（"再来 3 道""刚才第 2 题保留，其他重出"）。

### FR-11 调试台（P0，开发者用，不对普通用户开放）

见 [architecture.md §9](architecture.md)。核心要求：一个 query 进来，每一步的去向可视；图检索命中的节点与边一目了然；每次模型调用的提示、输出、token、缓存命中、延迟可展开；可从某一步重放；可一键把坏例子转为回归用例。

### FR-12 Badcase 闭环（P0，内部流程）

调试台 / 评测报告里发现的坏例子 → 标注根因类别 → 入 `eval/badcases/` → 修复 → 回归集防退化。流程见 [evaluation.md §6](evaluation.md)。

## 6. 澄清与默认值策略

| 缺失信息 | 处理 |
|---|---|
| 年级 / 范围完全缺失 | 提问一次（给常见选项：一年级……六年级 +"我不确定"）；用户选"不确定"则按最近一次会话范围，仍无则出三年级跨范围综合题并明示假设 |
| 题量缺失 | 默认 5 题 |
| 难度缺失 | 默认中等（3），分布略有梯度 |
| 题型缺失 | 按知识点自然题型（计算 / 应用 / 填空混合） |
| 档位缺失 | 先验：巩固 : 变式 : 综合 ≈ 3 : 4 : 3；用户说"拔高 / 综合"则偏综合 |
| 需求超出小学范围 | 说明范围，提供最接近的小学内容选项 |
| 与数学无关 | 简短说明能力范围，不执行 |

## 7. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 性能 | 见 FR 各 AC；目标值初版为暂定，基线后校准 | D1–D4 |
| NFR-2 可靠 | 单次运行成功率 ≥ 99%；模型 429 / 超时有重试与降级，不让用户看到堆栈 | F1–F4 |
| NFR-3 成本 | 单题与单卷成本有预算上限，超限降级（如跳过盲解） | E1–E3 |
| NFR-4 可观测 | 每个运行有完整 trace，覆盖率 100%；指标全部由 trace 计算 | F6 |
| NFR-5 安全 | 上传内容中的指令不被执行（提示注入）；模型生成的代码只在受限沙箱执行；调试台需令牌 | G1–G2 |
| NFR-6 隐私 | 图片与会话数据按保留期清理（默认 30 天，可配）；日志不含密钥 | — |
| NFR-7 兼容 | 桌面 Chrome / Edge / Safari 最新两个主版本；移动端可浏览与导出，编辑体验按桌面优先 | — |
| NFR-8 可维护 | 模块分层边界由测试强制；新增阶段 / 工具 / 导出格式 / 指标有固定扩展点 | 见 architecture §10 |

## 8. 本期不做

账号与权限、付费与配额限制、教师协作与分享、班级学情数据、手写批改、语音输入、生图（场景插图，列入 P2 且需要图像模型接口）、多教材版本（只做北师大版）。

## 9. 发布标准（概要）

每个里程碑按 [roadmap.md](roadmap.md) 的出口标准验收；首个对外版本（M8）需同时满足：所有**闸门**指标达标（A2、A3、F1、C4）；北极星 A1 相对基线有可度量提升；评测集在 test 划分上通过；调试台可复现并定位任意一次运行；部署文档可由他人按步骤复现。

## 10. 开放问题

1. 主模型选型（qwen3.8 系列 / deepseek-v4.1-flash）——由角色级对比评测决定，不预设（D10）。
2. 导出 PDF 的引擎（Typst 路线 vs 无头浏览器路线）——由 M1 的 S1 探针（排版保真、冷启动、镜像体积）决定。
3. 图形题的覆盖范围：首版 FigureSpec 支持哪些图形（数轴、长方形 / 三角形 / 角、条形统计图、方格图）——按评测集里图形题占比决定。
