## M0～M2：先把骨架和评测搭起来

- 需求来自[项目委托书](brief.md)与一线教师访谈：**正确性**与**意图对齐**是两个核心痛点。指标分北极星 / 闸门 / 目标 / 护栏 / 诊断五层（[metrics.md](metrics.md)）。
- 基建与能力分开：先做网关、trace、存储、沙箱、阶段框架与评测框架（M1），再做能力。模型调用可录制回放，回归测试无网络、无密钥、零成本（D10）。
- 理解阶段（M2）：路由并入理解、一次模型调用，其余由确定性代码完成（D29）；`fast` 角色选 deepseek-v4.1-flash（D30）；消融后删掉了没有收益的模块（D31）。

## M3（第一轮，2026-10-05～06）：核验先行，交付与"好题"的拉锯

- 先写评测再实现：核验集 1237 题、超纲集 136 题、端到端用例 72 + 留出 36；独立审计（两个不同厂商的思考模型解题，D37）。
- 生成：先算后写、答案结构化（D34）；核验：便宜的检查在前、模型检查并行（D35）；单题时间预算与修复上限（D36）；`template` 来源（D38）；删除没有收益的新颖度检查（D39）。
- 为"好题"探索了三种策略（候选择优 / 范例驱动 / 评审改稿），都没有采用，结论是杠杆在上游（D40）；随后加的四个"好题"开关让交付率从 0.90 降到 0.65、时延翻倍，只好拆成 `classic` / `design` 两条链路并存（D41）。这一轮留下的问题：题量达成率低、A2 / A3 未过闸门、对朴素直出的偏好盲评输多赢少。

## M4～M8：感知、试卷、导出、界面与对外评测

- 照片识别：视觉模型只做"读"，其余确定性；画质差由代码判断、暂停让教师核对（D51～D54）。
- 试卷：修订是线性、只增不删的历史；自然语言编辑 = 模型译成编辑计划 + 确定性执行（D43～D46）。
- 导出：片段化转换 + 自有版面 + "预览即导出"（D42）；前端状态是事件的纯函数，逐题上屏（D47～D50）。
- M8 在 test 划分上跑全链路：F1 / F5 / F6 / C4 / G1 过闸门，A1 0.855 对朴素直出 0.642；A2(a) 0.944、A3 0.048、题量达成率 0.775 未达标（[e2e §5](../eval/specs/e2e.md)）。

## M3（第二轮，2026-11-04）：回到规划，并让评测本身可信

这一轮从"教师会不会原样使用这道题"出发，先质疑评测，再动系统。

1. **把审计发现的问题题入库并逐条核对**（`eval/badcases/`）：M8 判"超纲"的 7 道里，3 道属实、2 道是审计误判（chalkbase 几何词表缺"容积"、不进位加法被归到"含进位"概念）、1 道疑似知识库边界过严、1 道真正的问题是偏题。A3 的审计口径本身需要校准。
2. **M8 的题量达成率是评测假象**：评测时 4 个用例同时跑、模型并发只有 8，题目排队、被 45 秒单题预算截断。并发给够后，同一条链路交付 0.97～1.0（评测命令已改正，eval/CHANGELOG.md）。
3. **北极星的代理看不到教师的要求**：读 classic 链路的全部交付题，教师不会原样使用的题主要是"不符合要求""把无关小问拼成综合题""同套雷同""数据荒谬"，而 A1 判据逐题评、看不到教师原话，这些题都算"可直接使用"。新增**教师视角评审**（带原话、看整套；与人工标注 κ 0.74），只用于比较，关键结论都读题确认（eval/CHANGELOG.md）。
4. **规划重构（D59）**：根因在规划——规划与写题看不到教师原话；主题检索不分年级，"三年级下册的乘法"映射到二年级的入门概念；骨架给每道综合题硬配一对知识点，写题只能拼接。改为**代码管约束**（范围、题量、档位、难度、题型、能力边界）+ **"本册优先"的候选菜单** + **模型读原话为整套题设计解题链与情境** + **代码校验合并**；删除两条链路与四个"好题"开关。在调优中从未使用的 18 个 val 请求上，可用 / 要求 0.65 → 0.83，偏好盲评 7 胜 5 负。试过没有保留的："巧思"要求（时延 +50%）、同套数字雷同检查（没有可度量收益）。
5. **写题可以带图（D60）**：渲染与导出早就支持四类图形，但写题从不产出规格。现在写题可给出一张图的结构化规格，由代码渲染校验；核验模型读图的确定性文字描述。在真实界面上验证时又修掉两处：逐题上屏阶段图形接口找不到图（破图）、条形统计图的纵轴标签被截断。
6. **核验各层的必要性与写题模型（D61）**：108 份原始初稿的反事实分析——盲解抓到 6 道答案错里的 5 道（求解程序只抓到 3 道），超纲检查独有抓取最多，不删任何一层；deepseek-v4.1-flash 写题更快更省但质量明显落后，写题保持 qwen3.7-plus。
7. **其他**：模型调用可选择走环境代理（`VERICHALK_LLM_USE_PROXY`，用于只能经代理出网的环境）；探针改走线上同一流程并报告时延与成本；自然语言编辑在新写题提示下复测 C1 12/13（`eval/reports/edit_m3_20261104-081856.md`；唯一失败是写题模型在求解程序里用了浮点数，修改未生效、原题保持不变）。
8. **留出集验收**（`produce_fresh`，36 例，从未用于调优；下面的题量达成率与按要求题数的指标后来发现被计分漏洞低估，见第三轮；前两次运行分别因审计高并发失败、模型服务中断作废，修好审计缓存后从头重跑一次，见 [produce.md §8.1](../eval/specs/produce.md)）：交付题答案正确 0.966（朴素直出 0.838）、已核验题 0.973、交付题可直接使用 0.829（0.699）；**但题量达成率 0.670，按要求题数算的可用率 0.524 低于朴素直出的 0.669**。原因是没见过的请求里大量"老师点名的主题只能靠看图出题 / 超出所说年级""只要计算题、课本那种基础题"之类的要求——规划换了主题、没守住形式，也没有告诉老师。验收中还发现并修掉一个崩溃（写题在条形图里用 `"?"` 表示被遮住的一栏）。

**留下的问题**（按影响排序）：①**需求贴合在没见过的请求上不稳**（上面第 8 条）：主题无法用文字或现有图形出题、或超出所说年级时，应当先告诉老师并给出选项，而不是换主题；老师要基础练习 / 指定题型 / 指定情境时，规划的"考法多样"不能盖过原话。②理解阶段对"超出所说年级"的请求不追问。③知识库数据：几何词表缺"容积"等（向 chalkbase 反馈）。④题面评审误杀约 7.5%。⑤图形只有四类基本图形。
**教训**：val 上调出来的改进（0.65 → 0.83）在留出集上没有同样成立——val 的请求多是"知识点 + 题量"的常规形态，留出集里形式要求、看图主题、年级错配多得多。下一轮的评测集要先覆盖这些形态，再动系统。

## M3（第三轮，2026-11-06～07）：需求贴合，v1 发布

这一轮先修评测，再动系统；每处改动都在开发集上对比，最后在新留出集上与 main、上一版、朴素直出四方对比。

1. **评测集按分布重建**（eval/CHANGELOG.md 2026-11-06）：留出集对齐真实场景（按教材比例：领域、年级、"只用配图题考的主题"约 1/4、请求形式），开发集对齐留出集；新留出集在改动之前写好封存。用过的留出集都降为开发集（现 89 例）。
2. **评测本身的四处修正**：①**计分漏洞**——丢弃后补上的题从没计入交付，题量达成率一直被低估（同一份旧代码，修正前后 0.78 对 0.951）；②教师视角评审不再因整套题量不足把单题判为不合格，也不把同类口算判为雷同；③审计此前看不到图，看图题一律"无法确定"、被判答错；④答案比较补齐写法差异（"红"与"红色"、"4元7角"、"百分之八十五"、"9π"——后两种此前会被解析成 100 与 9），审计结论改为计分时按当前规则重判。另加了跨版本对比的工具（`--save` / `--load`）与"审计 A1 ∧ 教师视角"的合并口径（`--teacher`）。
3. **需求贴合**（D62、D63）：根因都在规划与理解——菜单把只用配图题考的主题筛掉而换成了无关知识点；"四上的小数乘法"没有按四下出；老师没要的综合题、"只要计算题"里的找规律、课本式题型卡片不对题、同套撞数。开发集（48 例，同一计分）上教师视角可用率 0.567 → 0.727，端到端 p50 98s → 76s。
4. **图形与超纲判定**（D64、D65）：补了复式条形、折线、扇形统计图与钟面；钟面上的数不算整数范围，同一主线同一学年稍后的概念只请老师复核。
5. **试过、没有保留的**：题面评审对单知识点题判"主要考的是不是这个知识点"（消融无净收益、时延 +20s）；课本式请求改由模型原创（可用 33/54 对 46/54、慢 4 倍）。
6. **第一次发布验收**（2026-11-06）后读失败样本，又修了四类问题（课本式卡片不对题时换卡、配图类主题与指定情境不分配计算题、"稍超前"只看差不到两个年级的命中），于是**换了一份同分布的新留出集**做最终验收，并在验收前按产品可接受的水平校准了目标值（eval/CHANGELOG.md 2026-11-07）。
7. **最终验收**（[produce.md §8.1](../eval/specs/produce.md)）：v1 在"贴合老师要求"上领先旧版本（教师视角 0.660，上一版 0.613、main 0.546），超纲最少，端到端与 main 持平；答案正确 0.978，与上一版相当，远好于朴素直出。验收中 1 个请求运行失败（图形标注的写法未被正确处理，并行的其他题也没有收尾，trace 不完整），两处都已修复；修复后在留出集上的确认运行 41/41 正常。

**留下的问题**：①只看"贴不贴合要求"时，朴素直出的常规题更常被判可用（0.869 对 0.660）——v1 仍会把配图类主题带成算术题、课本式题型卡片偶有不对题、对主题范围理解偏宽；②知识库数据问题（课时归属、题型卡片的题面）已登记 `eval/badcases/`。
**教训**：评测本身要先接受检验——这一轮最大的几处"退步"与"差距"（题量 0.67、看图题答错）都是评测漏洞；开发集与留出集同分布之后，开发集上的改进在留出集上方向一致。
