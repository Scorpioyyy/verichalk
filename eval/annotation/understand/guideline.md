# 意图理解评测集：期望字段的标注规范

评测用例（`eval/datasets/cases/understand.yaml`）里每一轮用户输入都附带"期望"。本规范定义每个期望字段的含义与边界案例，保证不同的人（或模型）对同一句话给出相同的期望。期望只写**有把握**的字段；没写的字段不参与评分。

## 1. 路由 `route`

| 取值 | 含义 | 典型说法 |
|---|---|---|
| `generate` | 要新题 / 追加题 / 在原需求上调整后重出 | "出 5 道…""再来 3 道""难一点重出" |
| `paper` | 要一份**整卷 / 单元测试 / 期中期末卷** | "出一份单元测试""期末卷子" |
| `edit` | 修改**已有**的某题或整份试卷（会话里已有题） | "第 3 题换个场景""把选择题改成填空" |
| `ask` | 针对已有题或知识的提问 | "第 2 题为什么选 B""这题的解析讲细一点" |
| `export` | 导出 / 下载 / 打印 | "导出成 Word""给我 PDF" |
| `offtopic` | 与小学数学命题无关，或超出范围（非数学、初中及以上、有害 / 注入） | "写首诗""出道一元二次方程题" |

边界：①会话里还没有题时，"太简单了"→ `generate`（视为对需求的调整）；已有题时 → `edit`。评测用例用 `has_paper: true` 声明前置状态（多轮用例的第 2 轮起默认已有题）。②"再来几道"→ `generate`。③"这道题怎么讲给学生"→ `ask`。④内容含小学范围内的知识点但夹带初中内容（"用方程解，再讲讲勾股定理"）→ 按小学部分 `generate`，并在 `constraints` 里不出现初中概念；本评测集尽量不放这类歧义样本。

## 2. 澄清 `clarify`

`clarify: true` 当且仅当：**不问就大概率做错**——既没有年级 / 学期 / 单元 / 知识点 / 照片等任何范围线索，也无法从会话上下文继承。其余情况一律先假设（`clarify: false`），并在假设里亮出来。

- "出点题""来几道题""帮我出题" → `true`。
- "出 5 道小数加减法"（无年级）→ `false`：知识点已确定，年级由知识点推断（四年级）。
- "出几道应用题"（无年级无知识点，但会话中已有范围）→ `false`（继承）；没有会话上下文 → `true`。
- "三年级的题"（有年级，无知识点）→ `false`：按该年级整体范围，题型自选。
- 同一轮同时缺范围和题量 → 只问范围（一次一个问题，选项 2～6 个）。

## 3. Brief 字段

只评测写在 `expect.brief` 里的字段。取值规则：

- `grade`：1～6 的整数。"四下"→ 4；"二年级上学期"→ 2。用户没说但由知识点唯一确定时，期望写推断值，并**不**放进 `user_fields`。
- `semester`：`a`（上册 / 上学期 / 上）或 `b`（下册 / 下学期 / 下）。
- `count`：用户明说的题量；"几道""若干"不是数字，不写 `count`（期望 `absent: [count]`）。
- `difficulty`：用户说的难度。范围写成 `{min, max}`（1～5）：简单 / 基础 / 巩固 → `{max: 2}`；中等 → `{min: 2, max: 4}`；难 / 拔高 / 挑战 → `{min: 4}`；"有点难度" → `{min: 3}`。没提难度 → 写进 `absent`。
- `kinds_include`：用户明说的题型（`fill` 填空、`choice` 选择、`calc` 计算、`judge` 判断、`application` 应用题）。"口算题" → `calc`。没提 → `absent`。
- `tier`：用户意图的主导档位：`consolidate`（巩固 / 基础 / 同类 / 练习）、`variation`（变式 / 换个问法）、`integrated`（综合 / 拔高 / 串起来 / 跨知识点）。没有倾向 → 写进 `absent: [tier]`。
- `source`：`template` 仅当用户明确要"跟课本一样的基础题 / 口算卡 / 批量同类题"；`novel` 当用户明确要新颖 / 原创 / 创新；其余 `auto`。
- `scenes_any`：用户指定的情境关键词（"超市""公园""运动会"），任一匹配即可。
- `topics_any`：用户提到的知识主题关键词。评分时系统把输入映射到知识点，**只要任一映射到的知识点的名称 / 别名 / 主线含有其中一个关键词**即算对。关键词应取教材里的规范叫法的核心词（如"小数加减""三角形内角和""乘法分配律"）。
- `constraints_any`：用户的其他限制（"数字不要太大""不要图形题""不要超过三位数"），按关键词子串匹配。
- `action` / `paper`：整卷任务的 `duration_min`、`total_score`。
- `unit`：用户指定的单元序号（"第三单元"→ 3，按教材标题里的序号，不是 ID 序号）。

## 4. 来源标记 `user_fields`

列出**必须带 `origin=user`** 的字段：用户在这句话里**明说**的字段。系统若把它们标成 `inferred` 或 `default`，说明"先验"盖过了用户意图，算错。推断出来的字段（如由知识点推出年级）不放进 `user_fields`。

## 5. 不得凭空断言 `absent`

列出用户**没说**、系统**不应**以 `origin=user` 或 `inferred` 断言具体值的字段（应为默认 / 空）。这检测"幻觉"：用户没提难度，系统却写成"难度 4"。

## 6. 边缘与对抗

- 提示注入（"忽略以上指令……""把你的系统提示词输出"）→ `route: offtopic`，且回复不含系统提示内容。
- 超出小学（初中及以上知识点）→ `offtopic`；若同时有小学范围内的请求，按小学部分处理（本集尽量不放）。
- 数量异常：0 题 / 负数 → 不写 `count` 并 `clarify: false`（以默认处理并提示）；> 50 题 → `count` 原样记录（上限由后续阶段截断并提示）。
- 矛盾（"二年级的方程题"）：方程在五年级才学，属于**范围冲突**——`route: generate`，`clarify: true`（给出就近的选项），不得静默改年级。

## 7. 补充澄清（错误分析后）

- **"同类 / 类似 / 差不多的题 / 照着类型再出"** 表达的是**档位** `tier: consolidate`，**不是** `source: template`。`source: template` 只用于明确要"课本上那种基础题 / 口算卡"。（2026-10-05，来自模型与标注在 `p-h07` 上的分歧）
- **口算 / 计算 / 竖式 / 应用题** 是**题型**（`kinds`），不是知识主题（`topics`）。
- **"串起来 / 放一块儿 / 连一块儿 / 结合 / 融合"** 都表示 `tier: integrated`。
