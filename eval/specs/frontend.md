# 评测规格：U1 用户端 + D1 调试台（前端）

> 对应路线图 U1、D1；需求见 PRD FR-6/7/8/9/10/11/12、架构 §9 与 §12。**先写本规格，再实现**；结果写在 §5。
> 前端的产品标准是"清晰、简洁、美观"，这三个词都要落成可检查的东西，而不是主观感受。

## 1. 失败模式（从教师与开发者的使用场景推出）

| 编号 | 失败模式 | 后果 |
|---|---|---|
| U-F1 | 等待时界面静止或只有转圈，不知道在做什么 | 教师以为卡死、重复提交（违反 FR-9） |
| U-F2 | 公式渲染失败、横向溢出、被截断 | 题目不能用，信任崩塌 |
| U-F3 | 界面里出现内部概念（知识点 ID、archetype、borderline、rev…） | 违反产品原则 1"说老师的话" |
| U-F4 | 核验状态与题目不同步（后台复核完成了，卡片还写"待核验"） | 误导：违反"可信且诚实" |
| U-F5 | 手改 / 撤销 / 自然语言改之间状态错乱，丢改动或覆盖他人修改 | 丢数据 |
| U-F6 | 页面在窄屏溢出、按钮挤压、可点区域过小 | 移动端不可用（NFR-7） |
| U-F7 | 文字对比度不足、不能键盘操作、状态只靠颜色区分 | 可访问性缺陷 |
| U-F8 | 一屏里有太多同等权重的操作，教师不知道下一步 | 不清晰、不简洁 |
| U-F9 | 前端状态与服务端事件日志推导出的状态不一致（实时与回放不同） | 违反 D23；调试台无法信任 |
| U-F10 | 调试台看不出"这一步去哪了"：阶段、检索图、模型调用、题目证据缺任一 | 违反 FR-11，无法定位失败样本 |
| U-F11 | 断线 / 刷新后丢失进行中的运行或试卷 | 违反 D11 / FR-10 |

## 3. 设计量表（K11 逐屏打分：0 好 / 1 轻微 / 2 中等 / 3 严重）

1. **一个焦点**：这一屏的主操作是什么？只有一个视觉上最重的按钮 / 区域。
2. **层级**：标题、正文、辅助信息三级字号与灰度可区分；题干是页面上最醒目的内容。
3. **留白与对齐**：间距遵循 4px 栅格；同一列元素左对齐；没有"挤"的区域。
4. **颜色克制**：中性色为主，强调色只用于主操作与状态；状态有图标或文字，不只靠颜色。
5. **文案**：教师语言；动词开头的按钮；错误信息说清原因与下一步；无英文标识外漏。
6. **反馈**：任何异步操作都有即时状态（进行中 / 完成 / 失败）；空状态有引导。
7. **数学排版**：公式与正文基线对齐、字号协调；填空横线、选项排列接近试卷。
8. **稳定**：内容流入时不跳动（骨架位、固定高度）；长内容折叠而不是撑破布局。

## 5. 结果（2026-10-06）

**对 §2 的一处修订（实现时发现更合理）**：K1 原写"reducer 推出的试卷等于服务端试卷"。实现时没有在前端重新实现补丁（那会有两套补丁语义），而是让 reducer 只推导**运行状态**（进度、检查点、回复、逐题送达、核验状态、试卷版本号），试卷内容由服务端持有、收到 `paper.patch` / `item.status` 后去取（D47）。K1 因此改为："对同一事件序列，分段送入（断线续传）与一次送入结果相同；重复事件被忽略；检查点之后的事件使运行恢复"（`reducer.test.ts`、`sse.test.ts`）。

| 单元 / 组件（vitest） | **82 个通过**：公式解析 15、事件 reducer 7、SSE 8、会话控制器 12、核验徽标 / 题目卡片 8、编辑器 7、检查点卡片 5、假设芯片 6、调试台模型 11、公式语料 3 |

**过程中发现的后端缺口（已修，见 CHANGELOG）**：①PRD 要求的"逐题上屏"在后端并没有实现（整份试卷全部完成才装配）→ `item.delivered`（D48）；②样题把总分摊给 3 道题；③未知 `/api/*` 路径回退成页面；④Windows 下由无控制台的父进程拉起服务时，求解程序子进程偶发"异常退出"（0xC0000142），整批题目被丢弃 → 子进程不再申请控制台。

**未做 / 风险**：拍照上传（M4）；调试台"从某阶段重放"与两次运行对比；只测了 Edge（Chromium），Safari / Firefox 未测；没有真实教师的可用性测试；深色模式不做。
